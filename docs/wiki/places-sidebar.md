# Places sidebar / Orte-Seitenleiste

## English

The sidebar shows your home folder, existing XDG folders, bookmarks, trash, saved connections and mounted storage. Unmounted fstab locations appear with an explanation. Eligible entries with `user`, `users` or `owner` can be mounted by clicking them. `owner` requires ownership of the device; unmounting a `user` entry requires a matching mounting-user record. Unknown ownership disables the action. The system helper checks the actual permission, while a busy dialog prevents navigation during mounting. Automount locations activate when opened. Devices requiring udisks/polkit, eject and LAN discovery belong to later steps.

F9 shows or hides the sidebar; Shift+F9 switches between the icon rail and full width. Existing custom shortcuts are preserved. The command palette also offers these actions and **Focus sidebar**. The bookmark Ribbon appears only while the sidebar is hidden. Alt+1–9 works in every mode.

Click opens the active pane, Ctrl+click/Ctrl+Enter the other pane, and middle-click/Shift+Enter a new tab. Arrow keys, Home/End and typing navigate the tree; Escape returns to the file list. Sections collapse. Right-click or Shift+F10 opens actions for navigation, connection management, properties, hiding entries and restoring hidden entries. Bookmarks can be edited or removed; Delete offers Undo.

Drag files from either pane onto a sidebar destination to open the existing transfer dialog with that destination. Hold Shift to move instead of copy. Archive, read-only, disconnected and unmounted destinations are refused. Drops work on the icon rail too. Drop exactly one folder between bookmarks or on the Places heading to pin it; drag bookmarks to reorder them. External application drags are not supported.

Click Trash to open the system file manager. Dropping files on Trash asks for confirmation and uses the normal trash job and undo history. **Empty trash** asks separately: it permanently purges owned trash directories on known local filesystems and cannot be undone. Network, non-block-device FUSE and automount filesystems are skipped, as are trash directories containing nested mounts. Local support includes bcachefs, JFS, overlay and fuseblk (for example ntfs-3g USB drives). Owned 0755 trash directories are accepted; group/other write access and symlinks replacing Trash, files or info are refused. A symlinked home or data directory is resolved once with a bounded wait before mount classification. Folder deletion uses an explicit stack and checks each opened directory against the trash root’s device, refusing newly encountered filesystem boundaries. Purging has no total time limit: a 30-second watchdog resets after each deleted entry, including children of trashed folders, and pauses at job checkpoints. Cancellation stops subsequent entries; a stalled kernel operation can finish later while retaining its mount reservation. Disposable trash-size caches are invalidated after deletion. The drop confirmation shows at most 20 paths plus the remaining count, but acts on the entire selection.

The context menu can save supported mounted network shares or fstab network entries as connections. Credentials and account names are not copied; enter any required account information in the connection editor. **Unmount** supports eligible fstab entries and GVfs mounts, including mounts without a saved profile. KIO-FUSE mounts can be saved and opened, but have no unmount action in this step. Before unmounting, affected tabs are checked, including inactive, locked, archive and symlink tabs. System profiles offer Unmount rather than Disconnect. Confirmation is required if any are inside the mount. They return home only after success; their old lock and history are cleared. A failed operation keeps the tabs in place.

The backend reserves source and destination paths for queued, running and paused jobs, including searches, comparisons, scans and undo. It refuses overlapping unmounts and refuses job admission during unmount. Reservations include canonical aliases and nested mounts; operations over a parent folder may conservatively keep child mounts busy. Emptying the trash reserves only existing trash directories; a stuck worker retains those reservations without blocking unrelated unmounts. Admission probes use a separate pool with one outstanding probe per mount or top-level path. Each job reads one bounded mount-table snapshot and resolves each distinct parent directory once; selected symlinks remain checked. Leaf checks use an inactivity watchdog, so large selections on a slow but responsive mount have no total admission deadline. Concurrent requests for the same mount wait within their own bounded wait budget while its current probe makes progress; a stalled probe refuses further work only for that mount. Mount helpers run without a shell and return safe error codes. After timeout, the backend checks mount state again and retains the reservation until the helper actually exits.

Properties show the safe device source, filesystem, read-only state and fstab permission flags when available. Free space can be requested explicitly for mounted locations. Mount changes are detected live; GVfs/KIO is polled every five seconds while the sidebar and window are visible. Dolphin network locations require KIO-FUSE. Filesystem probes have response deadlines and fixed worker limits; the last complete snapshot may remain visible when a filesystem is unreachable. GVfs/KIO paths containing sign-in information remain unavailable for sidebar navigation. Supported save/unmount actions use opaque keys, and tab checks return indices without exposing those paths.

Drag the separator to resize from 160 to 400 pixels; persistence happens on release. Drag below the snap threshold or double-click to switch to icons. Floating windows grow or shrink with the sidebar. X11 can also adjust position within the monitor work area. **Wayland applications cannot position their windows**; they grow to the right. Maximized, fullscreen and compositor-constrained windows use available space. When space is limited, the sidebar temporarily becomes an icon rail without changing the saved mode.

## Deutsch

Die Seitenleiste zeigt den persönlichen Ordner, vorhandene XDG-Ordner, Lesezeichen, den Papierkorb, gespeicherte Verbindungen und eingehängte Datenträger. Nicht eingehängte fstab-Orte erscheinen mit einer Erklärung. Berechtigte Einträge mit `user`, `users` oder `owner` lassen sich per Klick einhängen. `owner` setzt den Besitz des Geräts voraus; zum Aushängen eines `user`-Eintrags muss der einhängende Benutzer nachweislich übereinstimmen. Bei unbekannter Zuordnung bleibt die Aktion gesperrt. Das Systemprogramm prüft die tatsächliche Berechtigung; während des Einhängens verhindert ein Warte-Dialog die Navigation. Automount-Orte werden beim Öffnen aktiviert. Geräte mit udisks/Polkit, Auswerfen und Netzwerkerkennung folgen in späteren Schritten.

F9 blendet die Seitenleiste ein oder aus; Umschalt+F9 wechselt zwischen Symbolen und vollständiger Breite. Eigene Tastenzuordnungen bleiben erhalten. Die Befehlspalette bietet diese Aktionen und **Seitenleiste fokussieren**. Die Lesezeichenleiste erscheint nur bei ausgeblendeter Seitenleiste. Alt+1–9 funktioniert in jedem Modus.

Ein Klick öffnet den Ort im aktiven Fenster, Strg+Klick/Strg+Enter im anderen Fenster und Mittelklick/Umschalt+Enter in einem neuen Tab. Pfeiltasten, Pos1/Ende und Tippen navigieren im Baum; Escape führt zur Dateiliste zurück. Abschnitte lassen sich einklappen. Rechtsklick oder Umschalt+F10 öffnet Aktionen zum Navigieren, Verwalten von Verbindungen, Anzeigen von Eigenschaften sowie Ausblenden und Wiederanzeigen von Einträgen. Lesezeichen lassen sich bearbeiten oder entfernen; Entf bietet Rückgängig an.

Ziehe Dateien aus einem der beiden Fenster auf einen Ort, um den vorhandenen Transferdialog mit diesem Ziel zu öffnen. Umschalt bedeutet Verschieben statt Kopieren. Archive, schreibgeschützte, getrennte und nicht eingehängte Ziele werden abgelehnt. Das funktioniert auch auf der Symbolleiste. Genau einen Ordner zwischen Lesezeichen oder auf die Überschrift „Orte“ ziehen, um ihn anzuheften; Lesezeichen lassen sich durch Ziehen umsortieren. Ziehen aus anderen Anwendungen wird nicht unterstützt.

Ein Klick auf den Papierkorb öffnet den System-Dateimanager. Das Ablegen von Dateien auf dem Papierkorb fragt nach und verwendet den normalen Papierkorb-Auftrag samt Rückgängig-Verlauf. **Papierkorb leeren** fragt separat nach: Benutzereigene Papierkörbe auf bekannten lokalen Dateisystemen werden endgültig geleert. Netzwerk-, nicht blockgerätebasierte FUSE- und Automount-Dateisysteme sowie Papierkörbe mit untergeordneten Mounts werden übersprungen. Lokal werden auch bcachefs, JFS, overlay und fuseblk unterstützt, etwa ntfs-3g-USB-Laufwerke. Eigene Papierkorb-Verzeichnisse mit 0755 sind zulässig; Schreibrechte für Gruppe/Andere und Symlinks anstelle von Trash, files oder info werden abgelehnt. Ein verlinktes Home- oder Datenverzeichnis wird vor der Mount-Zuordnung einmal mit begrenzter Wartezeit aufgelöst. Die Ordnerlöschung arbeitet mit einem expliziten Stapel und prüft jedes geöffnete Verzeichnis gegen die Gerätekennung des Papierkorbs; neu auftretende Dateisystemgrenzen werden nicht überschritten. Das Leeren kann nicht rückgängig gemacht werden und hat kein Gesamtzeitlimit: Eine Stillstandsüberwachung startet nach jedem gelöschten Eintrag neu, auch innerhalb gelöschter Ordner, und berücksichtigt Auftragspausen. Erst nach 30 Sekunden ohne Fortschritt greift die Zeitüberschreitung. Abbruch verhindert weitere Einträge; eine hängende Kernel-Operation kann später enden und hält bis dahin ihre Mount-Reservierung. Größen-Caches werden nach Löschungen invalidiert. Die Drop-Bestätigung zeigt höchstens 20 Pfade und die Anzahl weiterer Einträge; die Aktion umfasst weiterhin die gesamte Auswahl.

Das Kontextmenü kann unterstützte Netzwerk-Mounts oder fstab-Netzwerkeinträge als Verbindungen speichern. Zugangsdaten und Anmeldenamen werden nicht übernommen; benötigte Kontodaten ergänzt du im Verbindungseditor. **Aushängen** unterstützt berechtigte fstab-Einträge und GVfs-Mounts, auch ohne gespeichertes Profil. KIO-FUSE-Mounts lassen sich speichern und öffnen, haben in diesem Schritt aber keine Aushängen-Aktion. Vor dem Aushängen werden alle betroffenen Tabs geprüft, einschließlich inaktiver, gesperrter, Archiv- und Symlink-Tabs. Systemprofile bieten dafür ausschließlich „Aushängen“ an. Liegen Tabs auf dem Mount, erscheint eine Rückfrage. Erst nach Erfolg wechseln sie nach Home; ihre alte Sperre und ihr Verlauf werden entfernt. Bei einem Fehler bleiben sie unverändert.

Das Backend reserviert Quell- und Zielpfade für wartende, laufende und pausierte Aufträge, einschließlich Suche, Vergleichen, Analysen und Rückgängig. Es verweigert überlappende Aushängungen und neue Aufträge während des Aushängens. Reservierungen berücksichtigen aufgelöste Pfad-Aliase und untergeordnete Mounts; Aufträge über einen übergeordneten Ordner können vorsorglich auch untergeordnete Mounts blockieren. Beim Leeren werden nur vorhandene Papierkorb-Verzeichnisse reserviert. Ein hängender Worker hält diese Reservierungen, blockiert aber keine unbeteiligten Aushängungen. Die Auftragszulassung verwendet einen eigenen Pool mit höchstens einer ausstehenden Prüfung je Mount oder oberstem Pfad. Jeder Auftrag liest die begrenzte Mount-Tabelle einmal und löst jedes gemeinsame Elternverzeichnis nur einmal auf; ausgewählte Symlinks werden weiterhin geprüft. Diese Dateiprüfungen überwachen Stillstand statt Gesamtdauer: Große Auswahlen auf langsamen, aber antwortenden Mounts scheitern dadurch nicht an einem Gesamtzeitlimit. Gleichzeitige Anfragen für denselben Mount warten innerhalb ihrer eigenen begrenzten Wartezeit, solange dessen laufende Prüfung Fortschritt macht; eine hängende Prüfung sperrt weitere Arbeit nur für diesen Mount. Mount-Helfer laufen ohne Shell und geben sichere Fehlercodes zurück. Nach einer Zeitüberschreitung wird der Mount-Zustand erneut geprüft; die Reservierung bleibt bis zum tatsächlichen Ende des Helfers bestehen.

Eigenschaften zeigen die bereinigte Gerätequelle, das Dateisystem, Schreibschutz und fstab-Berechtigungsoptionen, soweit vorhanden. Freier Speicher lässt sich für eingehängte Orte ausdrücklich ermitteln. Mount-Änderungen werden laufend erkannt; GVfs/KIO wird bei sichtbarer Seitenleiste und sichtbarem Fenster alle fünf Sekunden geprüft. Dolphin-Netzwerkorte benötigen KIO-FUSE. Dateisystemprüfungen haben Antwortfristen und feste Worker-Grenzen; bei unerreichbaren Dateisystemen kann der letzte vollständige Stand sichtbar bleiben. GVfs/KIO-Pfade mit Anmeldedaten bleiben für die Sidebar-Navigation gesperrt. Unterstützte Speichern-/Aushängen-Aktionen verwenden undurchsichtige Schlüssel; Tab-Prüfungen liefern nur Indizes und legen diese Pfade nicht offen.

Der Trennstrich lässt sich auf 160 bis 400 Pixel ziehen; gespeichert wird beim Loslassen. Unterhalb der Einrastgrenze oder per Doppelklick erscheint die Symbolansicht. Frei schwebende Fenster wachsen oder schrumpfen mit der Leiste. X11 kann zusätzlich ihre Position innerhalb des Monitor-Arbeitsbereichs anpassen. **Unter Wayland dürfen Anwendungen ihre Fenster nicht positionieren**; sie wachsen nach rechts. Maximierte, Vollbild- und vom Fenstermanager begrenzte Fenster nutzen den vorhandenen Platz. Bei Platzmangel erscheint vorübergehend die Symbolansicht, ohne die gespeicherte Einstellung zu ändern.
