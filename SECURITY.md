# Security policy / Sicherheitsrichtlinie

## English

### Supported scope

This policy covers Dualfile's code and packaging in this repository. It is a development snapshot; there is no promised security-support window for a released version. Include the exact version or commit in reports.

### Private reporting

Use [GitHub Security Advisories: report a vulnerability](https://github.com/Bexxs75/dualfile/security/advisories/new). Do not open a public issue or pull request containing exploit details, private files or credentials.

Include the affected version, Linux distribution, impact, reproduction steps and a minimal example with synthetic data. Relevant areas include destructive file operations, archive extraction, remote authentication and plugin permissions. Do not send real passwords or keys.

Private vulnerability reporting must be enabled by a repository administrator. Its availability has not been checked here. If the private form is unavailable, open an issue **only requesting activation of private reporting**, without vulnerability details. Wait for a private reporting channel before sharing details.

Maintainers will investigate, coordinate a fix and disclose the resolution when appropriate. No response-time guarantee is made. Please allow time to investigate before public disclosure.
